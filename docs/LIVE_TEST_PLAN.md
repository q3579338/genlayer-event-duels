## 逐笔验收与材料

1. 先部署候选，仅使用测试网网络费用，附带充值金额为 0。最终确认后核对完整源码。旧失败创建仍可独立只读查询，部署不能清除它的历史回执。
2. 先跑最小存取闭环：甲方独立 `deposit()` 充值 0.001 test GEN，核对 finalized 额度与外部余额；再 `withdraw()` 并核对后续外部转账和钱包真实到账。任一步不符即停止追加资金，不把父交易成功当作到账。
3. 存取通过后双方分别充值，再发 `create_duel(..., stake_wei)`、`accept_duel(id)`。这两个方法为 nonpayable，前端实际附带 value 必须是 0。保存每笔哈希、钱包、附带 wei、共识状态、执行结果，确认 `OPEN → ACTIVE`、双方地址、等额金额和锁定资金；失败后独立读取额度。
4. 事件截止后由参与钱包请求裁决：记录真实 GitHub 证据字段、YES/NO/UNKNOWN、核验次数与时间。`ACCEPTED` 不是最终确认；执行错误不是成功。
5. 明确结果进入胜方额度；胜方签名 `withdraw`。保存父交易回执、发出的外部消息/转账链接、提取前后余额及网络费用，核对真实到账。仅额度归零不足以通过。
6. 单独取消一个未匹配挑战，核对创建者额度、禁止重复取消和提取。
7. UNKNOWN 路径最早在事件截止 72 小时后执行真实退款；先记录本地与合约单测覆盖，真实验证完成前保持待验证。不得为演示缩短这条规则。
8. 把新增交易和状态加入可复查材料，再更新 Explorer 同一条目。只有实际提交后，才能写“已重新提交”；记录 Portal 返回的状态。
