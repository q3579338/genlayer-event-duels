# Bradbury 双钱包验收计划

本计划截至 2026-10-19 尚待真实钱包签名。未执行的步骤不能填作通过。不要用本地模拟或部署成功代替完整资金流程。

## 固定条件

- 合约仍使用已经最终确认的 `0x3cE9F1A0143f77405784F47Aa56467013c3846E9`，本次不改合约规则或重部署。
- 前端 v0.1.1，合约 `event-duels/0.1.0`。钱包 chain ID 4221，单方最低投入 0.001 test GEN，网络费用另计。
- 两个参与钱包必须不同，并分别由用户在 MetaMask 中连接和确认交易。不得创建替代钱包、索取或保存私钥。
- 测试仓库使用本项目公开仓库；正式发布 v0.1.1 的说明可以作为已有事实的回归测试证据。此类测试不是对未知未来事件的真实预测。
- 建议功能标准：`The release notes explicitly announce exportable transaction records containing transaction hash, wallet, exact wei amount, and raw receipt.`
- 接受窗口至少保留一天，事件截止更晚；实际确认时间可能较长。由页面计算具体时间，发起后不得修改。

## 签名前准备

1. 检查公开站点及演示指南，确认 20 项自动测试和构建通过。
2. 运行 `npm run check:live`，保存最新只读部署、源码匹配和 finalized 状态快照。
3. 公开发布实际包含上述功能的 v0.1.1 Release，核对 GitHub 标签、非草稿、非预发布、发布时间及正文长度。不得为测试回填虚假的发布时间。
4. 核对两个钱包的 test GEN 余额。当前观察：`0xa9EE…888888` 约 100 test GEN；`0x378e…A2cdc` 为 0。官方 faucet 的领取要求为主网至少 0.01 ETH，不能要求用户为此购买或转入主网资产。若不满足，可由用户签名把已有 test GEN 分给第二钱包。

## 逐笔验收与材料

1. 甲创建，乙接受：保存每笔哈希、钱包、附带 wei、共识状态、执行结果，确认 `OPEN → ACTIVE`、双方地址、等额金额和锁定资金。
2. 事件截止后由参与钱包请求裁决：记录真实 GitHub 证据字段、YES/NO/UNKNOWN、核验次数与时间。`ACCEPTED` 不是最终确认；执行错误不是成功。
3. 明确结果进入胜方额度；胜方签名 `withdraw`。保存父交易回执、发出的外部消息/转账链接、提取前后余额及网络费用，核对真实到账。仅额度归零不足以通过。
4. 单独取消一个未匹配挑战，核对创建者额度、禁止重复取消和提取。
5. UNKNOWN 路径最早在事件截止 72 小时后执行真实退款；先记录本地与合约单测覆盖，真实验证完成前保持待验证。不得为演示缩短这条规则。
6. 把新增交易和状态加入可复查材料，再更新 Explorer 同一条目。只有实际提交后，才能写“已重新提交”；记录 Portal 返回的状态。

## 用户接手边界

钱包连接确认、签名、测试币转移、验证码由用户接手。其余准备、只读查询、表单填写、结果核对由 AI 完成。禁止主动找社区成员聊天或自动循环。
