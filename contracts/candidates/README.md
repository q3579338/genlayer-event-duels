# Event Duels 0.2.0 · 部署候选

此目录不是旧合约地址的源码，不得用它宣称旧部署已经修复。旧部署源码仍保留在上一级 `EventDuels.py`。

真实创建在旧合约执行出错，但附带的 0.001 test GEN 进入了其 EVM 余额，内部没有可提取额度。当前无法验证回收，因此候选改为：

1. `deposit()` 是独立、最小的 payable 入口，只给实际 sender 记账。
2. `create_duel(..., stake_wei)` 与 `accept_duel(id)` 均为 nonpayable，只锁定已有额度，前端不附带新的转账。
3. 创建／接受的校验失败不会抹除此前独立交易充值的额度；余额可另行提取。
4. 权限按 immediate sender 判断，不用 origin 代替身份认证；提现固定给该 sender，不能指定另一人的额度。
5. 只有部署最终确认并与候选全文源码匹配，网页才开放写操作。

`npm run check:candidate` 通过远程 GenVM 提取接口、检查原构造函数，并在只读构造函数场景中模拟原生充值、拒绝无效创建、有效创建、取消及提现消息生成。它不广播交易，也不能证明独立链上交易、AI 共识或外部到账。

待完成：新部署、0.001 test GEN 充值后独立读取额度、原路提现实际到账，再进行双钱包挑战。直接向合约地址转账、ABI 解码前失败、GenVM/网络故障、外部转账失败仍可能产生未记账余额或其他损失；这仍是测试网原型。不得用主网资产测试。
